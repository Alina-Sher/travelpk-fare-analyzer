# Travel.pk Flight Price Trend Analyzer

A Streamlit dashboard showing how one-way economy fares change over time on five routes
(LHE→KHI, KHI→ISB, LHE→ISB, LHE→DXB, ISB→DXB). Built by TechAbout as a task prototype for Travel.pk.
It is **not** an official Travel.pk product.

> **DEMO DATA — These fares are simulated for demonstration and are not live airline prices.**
> The bundled dataset is generated by `scripts/generate_sample_data.py`. It is not real market data,
> and the app calls **no** live API.

## Features
- KPI cards (routes, observations, lowest / average / highest fare, change over period), all computed from the active filters
- Filters: origin, destination, route, airline, observation date range, travel date
- Interactive Plotly trend chart: compare routes, or one route by airline; hover shows route, date, fare, airline(s), source
- Route comparison table (count, min / avg / max, first / last observation, % change or `N/A`)
- Descriptive route summaries (no forecasts), data-quality warnings, empty-state message
- CSV download of the filtered rows, and a data viewer
- "Data Sources & Methodology" page, whose figures are computed from the loaded file

## 1. Prerequisites
Python 3.11 or newer (3.12 works), `pip`, and Git. A GitHub account and a Streamlit Community Cloud account are needed only for deployment.

## 2. Virtual environment
```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
```

## 3. Install dependencies
```bash
pip install -r requirements.txt
```
`streamlit` is pinned below 1.50 because the app uses `use_container_width`, which newer releases deprecate.

## 4. Run locally
```bash
streamlit run app.py
```
Open http://localhost:8501.

## 5. Run the tests
```bash
python -m unittest discover -s tests -v     # no extra packages needed
# or: pip install pytest && pytest -v
```
`tests/test_app_smoke.py` and the chart test skip themselves unless Streamlit and Plotly are installed.
After step 3 they run, so you get the full suite.

## 6. GitHub repository
```bash
git init
git add .
git commit -m "Travel.pk Flight Price Trend Analyzer"
git branch -M main
# create an empty repo on github.com first (e.g. travelpk-fare-analyzer), then:
git remote add origin https://github.com/<your-username>/travelpk-fare-analyzer.git
git push -u origin main
```
Check that `.streamlit/secrets.toml` and `.env` are not committed (both are in `.gitignore`).

## 7. Deploy on Streamlit Community Cloud
1. Sign in at https://share.streamlit.io with GitHub and authorise access to the repository.
2. Click **Create app** → **Deploy a public app from GitHub**.
3. Repository: `<your-username>/travelpk-fare-analyzer`; Branch: `main`; Main file path: `app.py`.
4. Under **Advanced settings**, choose Python 3.11 or 3.12.
5. Click **Deploy**. When the build finishes, Streamlit shows your public URL (`https://<name>.streamlit.app`).
   **That URL is the live link to submit.** None exists until you deploy; this project has not been deployed.

## 8. Replace the dataset
Replace `data/flight_fares.csv` with a CSV that has these columns:
`recorded_at, origin, origin_code, destination, destination_code, airline, departure_date, fare, currency, source, is_simulated`

- Dates must be `YYYY-MM-DD`. `fare` is a positive number (blank = missing). Use one currency.
- Keep one definition for every fare (e.g. lowest one-way economy fare for that airline, route and travel date).
- Set `is_simulated` to `False` only for genuine observations. Put the true provenance in `source`.
  The DEMO banner shows whenever any row is `True` and disappears when none are.
- Only use data you are entitled to use. Do not scrape sites that forbid it.
- The loader rejects bad dates or missing columns and reports duplicates and invalid fares on the methodology page.

## 9. Data-source limitations
- The bundled fares are simulated from a seeded model (fares rise toward departure, plus noise and one built-in
  promotional dip on LHE→ISB). They reflect no real airline, website or market.
- Airline names are placeholders (`Simulated Carrier A/B/C`).
- Observations are every 3 days between 1 Jul and 26 Sep 2026, for two travel dates (15 Oct and 15 Nov 2026).
- Eight records have deliberately blank fares to demonstrate gap handling.
- Historical movement does not predict future fares, and the app makes no forecasts.

## 10. Optional API credentials
No API is integrated, so no credentials are needed. If you later add a licensed fare-data API:
- Never put keys in source code or commit them.
- Locally, create `.streamlit/secrets.toml` (git-ignored): `FARE_API_KEY = "..."`
- On Streamlit Community Cloud, open the app → **Settings → Secrets** and paste the same line.
- Read it in code with `st.secrets["FARE_API_KEY"]`.
- Write fetched observations into the CSV schema above with real `source` values and `is_simulated = False`.
